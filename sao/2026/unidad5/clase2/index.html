EL DILEMA ESTÁTICO: Capacidad Física vs. Lógica

En un arreglo estático, la reserva en RAM es fija (length). Para simular una colección dinámica introducimos la variable de control tope:

Tamaño Físico (arreglo.length)

Cantidad total de casilleros reservados en la memoria del sistema. No se puede modificar una vez creado. Marca el límite de desbordamiento (Overflow).

Tamaño Lógico (tope)

Cantidad real de elementos válidos actualmente cargados. Indica el próximo casillero libre disponible para insertar.

Condición de desbordamiento (Overflow)

Antes de insertar cualquier nuevo elemento, siempre debemos verificar if (tope < arreglo.length). Si tope == arreglo.length, el arreglo está lleno y no admite más datos.

INSERCIÓN EN VECTORES: Al Final vs. Al Inicio

La posición donde se inserta el nuevo dato determina la complejidad temporal del algoritmo:

1. Inserción al Final (al Tope) O(1) Inmediato 
public static boolean insertarFinal(int[] arr, int valor) {
    if (tope < arr.length) {
        arr[tope] = valor;
        tope++;
        return true;
    }
    return false; // Vector lleno
}

Directo: se guarda en la celda tope sin desplazar ningún elemento existente.

2. Inserción al Inicio (en 0) O(N) Corrimiento 
public static boolean insertarInicio(int[] arr, int valor) {
    if (tope >= arr.length) return false;
    
    // Corrimiento a la derecha (descendente)
    for (int i = tope; i > 0; i--) {
        arr[i] = arr[i - 1];
    }
    arr[0] = valor;
    tope++;
    return true;
}

Requiere "hacer espacio": empuja todos los datos una posición a la derecha.

Sentido del bucle para hacer espacio

El bucle de corrimiento a la derecha DEBE ser obligatoriamente descendente (i = tope; i > 0; i--). Si se recorre hacia adelante, el primer valor se copia sobre el segundo y se destruye toda la información.

MECÁNICA VISUAL: Corrimiento a la Derecha

Paso a paso para insertar el valor 99 en la posición 0 de un vector con tamaño físico length = 5 y tamaño lógico inicial tope = 3:

1. Estado Inicial
[0]: 10 [1]: 20 [2]: 30 [3]: 0 [4]: 0
2. i = 3 → arr[3]=arr[2]
[0]: 10 [1]: 20 [2]: 30 [3]: 30 ← copia [4]: 0
3. i = 2 → arr[2]=arr[1]
[0]: 10 [1]: 20 [2]: 20 ← copia [3]: 30 [4]: 0
4. i = 1 → arr[1]=arr[0]
[0]: 10 [1]: 10 ← copia [2]: 20 [3]: 30 [4]: 0
5. Inserción arr[0] = 99
[0]: 99 (nuevo) [1]: 10 [2]: 20 [3]: 30 [4]: 0
Resultado exitoso

Actualizamos tope = 4 (apunta a la celda libre [4]). Los datos se preservaron íntegros y aún queda capacidad física disponible.

El 1° se ubica en [4] y completa el vector (tope = 5).

PRÁCTICA GUIADA 1: Inserción de Múltiplos (Prob. 7)

Problema: Insertar un elemento con valor X + 1 inmediatamente detrás de cada elemento que sea múltiplo de 100 (X % 100 == 0). Retornar la cantidad de elementos insertados. (Versión base: asume capacidad física suficiente). 

public static int insertarDetrasDeMultiplos(int[] arr, int cantActual) {
    int insertados = 0;
    for (int i = 0; i < cantActual; i++) {
        if (arr[i] != 0 && arr[i] % 100 == 0) {
            // Abrimos espacio desde cantActual hacia la derecha
            for (int k = cantActual; k > i + 1; k--) {
                arr[k] = arr[k - 1];
            }
            arr[i + 1] = arr[i] + 1; // Insertamos X + 1
            cantActual++;
            insertados++;
            i++; // ¡CLAVE! Saltamos el elemento recién insertado
        }
    }
    return insertados;
}
¡Ojo con el bucle infinito! (i++)

Al insertar en i + 1, se debe avanzar i++ para saltar el valor nuevo y no volver a evaluarlo.

Desafío: Control de Límites Físicos

Modificar la función considerando la validación de no exceder los límites físicos del arreglo (cantActual < arr.length) antes de desplazar.

ELIMINACIÓN EN VECTORES: Al Final vs. Al Inicio

Al borrar un dato, el objetivo es mantener la contigüidad de la memoria sin dejar "huecos vacíos" intermedios:

1. Eliminación al Final O(1) Inmediato 
public static boolean eliminarFinal(int[] arr) {
    if (tope > 0) {
        tope--; // Eliminación lógica
        return true;
    }
    return false; // Vector vacío (Underflow)
}

Instantáneo: decrementar tope-- ignora el último dato sin borrar físicamente la RAM.

2. Eliminación al Inicio (en 0) O(N) Compactación 
public static boolean eliminarInicio(int[] arr) {
    if (tope <= 0) return false;
    
    // Corrimiento hacia la izquierda (ascendente)
    for (int i = 0; i < tope - 1; i++) {
        arr[i] = arr[i + 1];
    }
    tope--;
    return true;
}

Compactación: cada elemento subsiguiente sobreescribe a su vecino izquierdo.

Bucle ascendente para compactar

Al eliminar, recorremos de forma ascendente (i = pos; i < tope - 1; i++). Traemos los datos de la derecha hacia la izquierda, pisando el elemento eliminado y cerrando el hueco.

PRÁCTICA GUIADA 2: Eliminación In Situ (Prob. 8)

Problema: Dado un vector ordenado, eliminar todos los elementos repetidos *in situ* (sin crear un arreglo auxiliar) y retornar la cantidad de elementos pares eliminados. 

public static int eliminarRepetidos(int[] arr, int tope) {
    int paresEliminados = 0;
    int i = 0;
    while (i < tope - 1) {
        if (arr[i] == arr[i + 1]) { // Encontramos un duplicado
            if (arr[i] % 2 == 0) paresEliminados++;
            
            // Compactamos a la izquierda sobreescribiendo arr[i+1]
            for (int k = i + 1; k < tope - 1; k++) {
                arr[k] = arr[k + 1];
            }
            tope--; // ¡NO incrementamos i! Podría haber otro repetido
        } else {
            i++; // Solo avanzamos si no hubo eliminación
        }
    }
    return paresEliminados;
}
¿Por qué usar while en lugar de for?

Si el arreglo tiene { 2, 2, 2, 5 } y borramos el segundo 2, el tercer 2 cae en la posición actual. Si avanzáramos ciegamente el índice, ese tercer 2 quedaría sin evaluar.

ANÁLISIS TEMPORAL: Resumen Big-O en Arreglos

Comportamiento algorítmico según la posición y la naturaleza de la operación:

Operación Posición Complejidad Justificación Mecánica
Acceso / Modificación Cualquier índice O(1) Cálculo aritmético de puntero directo en RAM.
Inserción Al final (tope) O(1) Asignación inmediata en la casilla libre de tope.
Inserción Al inicio o medio O(N) Requiere desplazar hasta N elementos a la derecha.
Eliminación Al final (tope) O(1) Basta con decrementar el contador tope--.
Eliminación Al inicio o medio O(N) Requiere desplazar todos los elementos a la izquierda.
Conclusión Arquitectónica

Los arreglos estáticos son insuperables en acceso por índice y operaciones al tope O(1), pero penalizan con corrimientos O(N) las inserciones y borrados en posiciones intermedias.
