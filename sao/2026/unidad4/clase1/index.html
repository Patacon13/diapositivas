Descomposición Modular // Fundamentos

Es una técnica de ingeniería de software donde un problema complejo se divide en subprogramas autónomos, lógicos, manejables y con propósito específico denominados módulos.

Principio: "Divide y Vencerás"

Resolver varios problemas pequeños y bien delimitados es inmensamente más simple y confiable que abordar un único bloque monolítico.

Programa Principal (main)
Módulo 1 (Cálculo)
Módulo 2 (Validación)
Módulo 3 (Reporte)

¿Por Qué Modularizar? // Pilares de Calidad

Reducción de Complejidad

Descompone la solución en piezas digestibles. El programador solo atiende una tarea a la vez.

Reutilización (DRY)

Don't Repeat Yourself. Un módulo se escribe una sola vez y se invoca múltiples veces desde cualquier lugar.

Legibilidad y Mantenimiento

El código se auto-documenta. Si surge un error, se aísla de inmediato en la función responsable.

Limitación de Cambios

Optimizar o corregir el algoritmo interno de un módulo no afecta al resto del sistema llamador.

Principio de la Caja Negra // Abstracción

Un módulo actúa como una caja negra: el invocador solo necesita conocer qué hace (su contrato de entrada y salida), sin preocuparse por cómo está implementado internamente.

Entrada (Parámetros)
int a, int b

MÉTODO MODULAR

Detalles internos ocultos
(Algoritmo encapsulado)

Salida (Return)
int resultado
Evolución en los Lenguajes

En programación estructurada (Pascal, C) se denominan Funciones (con retorno) y Procedimientos (sin retorno). En Java y POO, todos los subprogramas son Métodos pertenecientes a una clase.

Paquete java.lang // Métodos de Math

La clase Math provee funciones matemáticas estáticas que no requieren instanciación (se invocan directamente como Math.metodo(...)):

Método Descripción Ejemplo en Java Resultado
Math.abs(x) Valor absoluto de un número Math.abs(-25.4) 25.4
Math.pow(x, y) Potencia $x^y$ ($x$ elevado a $y$) Math.pow(2.0, 5.0) 32.0
Math.sqrt(x) Raíz cuadrada de $x$ Math.sqrt(144.0) 12.0
Math.ceil(x) Redondeo hacia arriba (menor entero $\ge x$) Math.ceil(9.2) 10.0
Math.floor(x) Redondeo hacia abajo (mayor entero $\le x$) Math.floor(9.8) 9.0
Math.max(x, y) Retorna el mayor entre dos valores Math.max(14, 29) 29

Azar en Java // java.util.Random

En computación los números son pseudo-aleatorios: se obtienen mediante un algoritmo determinista uniforme a partir de una semilla (seed).

Generación de Rangos

rnd.nextInt(n) produce enteros en $[0, n-1]$. Para simular un dado de 1 a 6: rnd.nextInt(6) + 1.

Pasos de Uso en Java: 

// 1. Importar el paquete
import java.util.Random;

// 2. Crear el objeto generador
Random rnd = new Random();

// 3. Invocar métodos de azar
int dado = rnd.nextInt(6) + 1; // 1 a 6
double prob = rnd.nextDouble();  // 0.0 a 1.0

Práctica Guiada // Simulación de Dados

Simulemos la tirada de un dado de 6 caras repetida 10 veces, registrando las salidas por consola: 


import java.util.Random;

public class Main {
    public static void main(String[] args) {
        Random rnd = new Random();
        System.out.println("=== 10 TIRADAS DE UN DADO ===");
        
        for (int i = 1; i <= 10; i++) {
            int tiro = rnd.nextInt(6) + 1; // Genera entre 1 y 6
            System.out.println("Tiro #" + i + ": " + tiro);
        }
    }
}

Anatomía de un Método // Declaración

En la cátedra SAO declaramos métodos con public static para invocarlos directamente dentro de la misma clase sin instanciar objetos:

public static Modificadores
int Tipo de Retorno
producto Identificador (Nombre)
(int a, int b) Parámetros Formales
    return a * b; // Sentencia de retorno obligatoria
}
Funciones vs Procedimientos

Si el método devuelve un dato, declara su tipo (int, double, boolean) y exige return. Si no retorna nada, se declara con tipo void (procedimiento de efecto colateral, ej: imprimir por pantalla).

Parámetros y Ámbito // Pasaje por Valor

1. Pasaje Estricto por Valor

En Java los primitivos se pasan por copia. Modificar un parámetro formal dentro del método NO altera la variable original del main.

2. Ámbito (Scope) de Variables

Las variables declaradas dentro de un método nacen al llamarlo y se destruyen al retornar. Ningún otro método puede acceder a ellas directamente.

Call Stack (Memoria RAM)
Marco del Método: producto()
int a = 3; int b = 9; (copias locales)
Marco Principal: main()
int n1 = 3; int n2 = 9; (intactas)

Caso de Estudio // Producto Simple (URI)

Problema: Leer dos enteros y mostrar PROD = X delegando el cálculo a un método.

Comparación Algorítmica:

Solución 1 (Directa): return a * b; — Eficiente e instantánea.

Solución 2 (Sumas Sucesivas): Sumar $a$ tantas veces como indique $b$. Eficaz pero consume más ciclos de reloj. 


public static int producto(int a, int b) {
    return a * b; // Contrato limpio
}

public static int productoSumas(int a, int b) {
    int acum = 0;
    for (int i = 0; i < Math.abs(b); i++) {
        acum += a;
    }
    return (b < 0) ? -acum : acum;
}

Práctica Guiada // Múltiplos y Potencias

Dada una secuencia de $N$ pares $(n_1, n_2)$: si $n_1$ es múltiplo de $n_2$ mostrar su suma, caso contrario mostrar su potencia ($n_1^{n_2}$): 


public static boolean esMultiplo(int n1, int n2) {
    return (n2 != 0) && (n1 % n2 == 0);
}

public static int suma(int a, int b) {
    return a + b;
}

public static double potencia(int base, int exp) {
    return Math.pow(base, exp);
}
El main queda limpio y declarativo:

if (esMultiplo(n1, n2)) System.out.println("Suma: " + suma(n1, n2)); else System.out.println("Potencia: " + potencia(n1, n2));
