Descomposición Modular // Fundamentos

Es una técnica de ingeniería de software donde un problema complejo se divide en subprogramas autónomos, lógicos, manejables y con propósito específico denominados módulos.

Principio: "Divide y Vencerás"

Resolver varios problemas pequeños y bien delimitados es inmensamente más simple y confiable que abordar un único bloque monolítico desordenado.

Programa Principal (main)
Módulo 1 (Cálculo)
Módulo 2 (Validación)
Módulo 3 (Reporte)

¿Por Qué Modularizar? // Pilares de Calidad

Reducción de Complejidad

Descompone la solución en piezas digestibles. El programador solo atiende una tarea a la vez.

Reutilización (DRY)

Don't Repeat Yourself. Un módulo se escribe una sola vez y se invoca múltiples veces desde cualquier lugar.

Legibilidad y Mantenimiento

El código se auto-documenta. Si surge un error, se aísla de inmediato en la función responsable.

Limitación de Cambios

Optimizar o corregir el algoritmo interno de un módulo no afecta al resto del sistema llamador.

Principio de la Caja Negra // Abstracción

Un módulo actúa como una caja negra: el invocador solo necesita conocer qué hace (su contrato de entrada y salida), sin preocuparse por cómo está implementado internamente.

Evolución en los Lenguajes

En programación estructurada (Pascal, C) se denominan Funciones (con retorno) y Procedimientos (sin retorno). En Java y POO, todos los subprogramas son Métodos pertenecientes a una clase.

Anatomía de un Método // Declaración

En la cátedra SAO declaramos métodos con public static para invocarlos directamente dentro de la misma clase sin instanciar objetos:

public static Modificadores
int Tipo de Retorno
producto Identificador (Nombre)
(int a, int b) Parámetros Formales
    return a * b; // Sentencia de retorno obligatoria
}
Funciones vs Procedimientos

Si el método devuelve un dato, declara su tipo (int, double, boolean) y exige return. Si no retorna nada, se declara con tipo void (procedimiento de efecto colateral, ej: imprimir por consola).

Parámetros y Ámbito // Pasaje por Valor

1. Pasaje Estricto por Valor

En Java los tipos primitivos se pasan por copia. Modificar un parámetro formal dentro del método NO altera la variable original del llamador en el main.

2. Ámbito (Scope) de Variables

Las variables declaradas dentro de un bloque nacen al llamarlo y se destruyen al retornar. Ningún otro método puede acceder a ellas directamente.

Call Stack (Memoria RAM)
Marco del Método: producto()
int a = 3; int b = 9; (copias locales)
Marco Principal: main()
int n1 = 3; int n2 = 9; (intactas)

Caso de Estudio // Multiplicación Básica

Problema de juez: Leer dos números enteros e imprimir su producto. Ver en OmegaUp
Comparación de Enfoques:

Solución 1 (Directa): return a * b; — Eficiente en tiempo constante O(1).

Solución 2 (Sumas Sucesivas): Sumar a tantas veces como indique b (2 × 13 = 2 + 2 + ... + 2). Es eficaz pero menos eficiente. 


public static int producto(int a, int b) {
    return a * b; // Contrato limpio
}

public static int productoSumas(int a, int b) {
    int acum = 0;
    int limite = Math.abs(b);
    for (int i = 0; i < limite; i++) {
        acum += a;
    }
    return (b < 0) ? -acum : acum;
}

Práctica Guiada // Múltiplos y Potencias

Consigna del Problema

Dada una secuencia de N pares de números (n1, n2): si n1 es múltiplo de n2 mostrar su suma, caso contrario mostrar su potencia (n1n2).

Condición 1: n1 es múltiplo de n2

Acción requerida: calcular y mostrar Suma = n1 + n2.

Condición 2: n1 NO es múltiplo

Acción requerida: calcular y mostrar Potencia = n1n2.

Casos de Prueba (Entrada → Salida):
  • Par (10, 5) → 10 es múltiplo de 5 → Suma: 15
  • Par (2, 3) → 2 no es múltiplo de 3 → Potencia: 8.0
  • Par (12, 4) → 12 es múltiplo de 4 → Suma: 16
  • Par (3, 2) → 3 no es múltiplo de 2 → Potencia: 9.0
Pregunta disparadora:

¿Qué métodos con retorno podemos definir para aislar cada operación y mantener el método main limpio y declarativo?

Práctica Guiada // Solución Modular

Descomponemos la lógica en tres métodos estáticos independientes con tipos de retorno adecuados: 


// 1. Verificación booleana (controlando división por cero)
public static boolean esMultiplo(int n1, int n2) {
    return (n2 != 0) && (n1 % n2 == 0);
}

// 2. Operación aritmética de suma
public static int suma(int a, int b) {
    return a + b;
}

// 3. Operación de potencia (reutilizando biblioteca Math)
public static double potencia(int base, int exp) {
    return Math.pow(base, exp);
}
El main queda limpio, legible y declarativo:

if (esMultiplo(n1, n2)) System.out.println("Suma: " + suma(n1, n2)); else System.out.println("Potencia: " + potencia(n1, n2));
