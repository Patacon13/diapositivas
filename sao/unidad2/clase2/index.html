SUFIJOS: ¿Por qué existen en Java?

Cuando escribimos un número directamente en el código, el compilador debe deducir a qué tipo pertenece ese literal:

Enteros sin sufijo

Java asume automáticamente que son de tipo int (32 bits con signo).

Decimales sin sufijo

Java asume automáticamente que son de tipo double (64 bits, doble precisión).

El Problema:

Si queremos usar un literal fuera del rango por defecto de int o almacenar un decimal en un float, el compilador requiere una indicación explícita. ¡Ahí entran los sufijos!

SUFIJOS: Ejemplos Prácticos

Ejemplo 1 — Enteros Grandes:

long g = 10000000000; // ❌ Error: fuera de rango int
long g = 10000000000L; // ✔️ Compilador sabe que es long

Ejemplo 2 — Decimales con float:

float iva = 0.21; // ❌ Error: 0.21 es double por defecto
float iva = 0.21f; // ✔️ Con f, se fuerza a float (32 bits)

Tipo de Dato Ejemplo Válido Detalle y Recomendación

Abreviadas Unarias

Abreviadas Binarias

Regla Clave: El valor y tipo resultante dependerá de los tipos de datos de los operandos (ej: 5 / 2 da 2, pero 5.0 / 2 da 2.5).

PRECEDENCIA: Reglas de Evaluación

Operador Operación Orden de Evaluación
*   /   % Multiplicación, División, Resto Primero (de izquierda a derecha).
+   - Suma, Resta Después (de izquierda a derecha).
Para omitir reglas de precedencia o aclarar la intención, usá paréntesis ().
2 * 3 - 1
Multiplica primero: (2 * 3) = 6 → 6 - 1 = 5
5 + a * 100 / 60
Multiplica a * 100, luego divide por 60, finalmente suma 5.
2 * (3 - 1)
Paréntesis manda: (3 - 1) = 2 → 2 * 2 = 4

UNARIAS: Pre y Post Incremento

Operador Nombre Expresión Explicación del Momento de Evaluación
++ Preincremento ++a Incrementa a en 1 primero; luego utiliza el nuevo valor en la expresión.
++ Postincremento a++ Utiliza el valor actual en la expresión; luego incrementa a en 1.
-- Predecremento --b Decrementa b en 1 primero; luego utiliza el nuevo valor en la expresión.
-- Postdecremento b-- Utiliza el valor actual en la expresión; luego decrementa b en 1.

DESAFÍO: Evaluaciones Lógicas

¿Qué valor de verdad (true o false) arrojará cada sentencia en pantalla? 


public class ConectoresLogicos {
    public static void main(String[] args) {
        int a = 1, b = 2, c = 3;

        System.out.println("Evaluación (a==c): " + (a==c));               // ?
        System.out.println("Evaluación (a!=b): " + (a!=b));               // ?
        System.out.println("Evaluación !(a<b && b<c): " + !(a<b && b<c)); // ?
        System.out.println("Evaluación (a==b || a<b): " + (a==b || a<b)); // ?
        System.out.println("Evaluación (a<=b && a>3): " + (a<=b && a>3)); // ?
    }
}

CONVERSIÓN: Implícita y Explícita

Conversión Implícita (Widening)

El compilador adapta automáticamente las representaciones al pasar de un tipo de menor tamaño a uno de mayor tamaño. Sin riesgo de pérdida de datos.

Conversión Explícita (Casting / Narrowing)

El programador escribe explícitamente el tipo destino entre paréntesis (tipo). Necesario de tipos mayores a menores.

¡Ojo con el Desborde y el Truncamiento!

Un casting forzado hacia un tipo de menor capacidad descartará los bits más significativos o truncará los decimales sin aviso en tiempo de ejecución.

Reflexión: En la expresión 5 + a * 100 / 60, ¿qué valor arroja si a = 1?
Siendo a entero, 100 / 60 es una división entera truncada a 1 → 5 + 1 = 6.
Para obtener decimales, se requiere casting explícito o literal flotante: 5 + (double)a * 100 / 60 → 6.6666....

CASTING: Jerarquía de Tipos Básicos

byte1 byte
